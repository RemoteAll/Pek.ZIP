## 2026-11-18 立项目：Zig 版 IP 库（Pek.ZIP）

### 用户原话

> 帮我参考 `G:\Code\Rust\Pek.IP` 和 `G:\Code\Pek.FrameWork\DH.NIP` 这两个项目使用 ziglang 实现功能，同样要考虑性能以及根据全局用户指令做接续相关

> IP文档我还是想直接通过RPanelSever中的资源来在启动时异步判断是否存在，不存在就下载

### 背景

- Rust `Pek.IP` 已覆盖 xdb v3 + MMDB + 合并 + 组件源按需下载（Ed25519 + SHA-256 + 自动注册票据）。
- C# `DH.NIP` 覆盖纯真 `ip.gz`（GBK）+ 在线 API 多格式解析 + DB-IP CSV→纯真格式转换。
- 生态里已有 Zig 项目（`Pek.ZPermissions` 等）与接续基建模板，可直接装备。

### 决策

1. **范围（v0.1）**：xdb v3（v4/v6、Vector/BTree）、MMDB（City/Country/ASN/ISP）、纯真 QQWry（gzip + GBK）、特殊地址分类、双源合并、CLI、基准、启动异步下载管理。
2. **数据视图统一到 `Blob`**：xdb / mmdb / qqwry 三种格式都需要「整文件只读字节」，mmap/堆/借用与生命周期只写一份（`src/blob.zig`）。第二个副本出现即违规。
3. **零分配查询是硬口径**：`XdbReader.lookup` / `MmdbReader.lookupWorld|lookupAsn` / `Locator.lookup` 返回借用切片；QQWry 的 GBK→UTF-8 写调用方 `Scratch`。Rust 版返回 `String`，Zig 版在热路径上省掉全部分配。
4. **mmap 而非全量读入**：`File.createMemoryMap`（Zig 0.17 的 std 已跨平台实现，Windows/POSIX 都有；`no_mmap` 可退化）。v6 库 37 MiB 不进进程私有内存，多进程共享页缓存。
5. **启动异步 = 本地同步 + 后台线程 + 原子热替换**：
   - `Manager.start` 只做 mmap（毫秒级），立刻可查（哪怕一个库都没有：内网/保留地址照常识别）；
   - 缺失数据集在**后台线程**拉取（catalog → 选包 → 下载 → SHA-256 → 解压 → 安装 → 重建 → swap）；
   - 读方**不取锁**（原子加 + 指针复核）；被替换的旧定位器进「退休列表」，运行期不销毁，`destroy()` 统一回收 —— 这是 hazard pointer 的廉价替代，避免读者 use-after-free；
   - 选线程而非 await 的原因：std 0.17 在 Windows 上 socket 读是同步 `deviceIoControl`，真异步要自建 AFD/IOCP；接口保持可替换（POSIX 可换 `Io.concurrent`）。
6. **安全默认值**：配了 `PubKey` 但 Ed25519 验签未实现 → **拒绝下载**并在 `lastError()` 说明（不静默放行）；`StoreUrl` 为空 = 仅本地缓存；`DownloadV6=false`。
7. **GBK 码表用生成物**：`tools/gen_gbk_table.ps1`（.NET CP936）生成 `src/gb2312.bin`（24066×u16，48 KiB）；用二进制 + `@embedFile` 而不是 2.4 万行 Zig 字面量（源码瘦、编译快）。反向编码器运行时排序一次，供后续 CSV 转换用。
8. **接续基建全套装备**：`.github/copilot-instructions.md`、`docs/{项目接续指南,用户档案,项目记忆,决策记录}.md`、`tools/continuity/*`（从 `Pek.ZPermissions` 字节级复制）、`.vscode/tasks.json`（打开项目自检）、`tools/regression.ps1`。
9. **CLI 默认离线**：`zpk lookup` 默认只读本地（`background=false`），避免「平台不可达导致命令行卡住」；要演示启动异步用 `--online`（后台补缺 + 等下载结束再退出），批量部署用 `zpk sync`。

### 已知缺口（v0.1 明确不做，写在这里防遗忘）

- **Ed25519 验签与自动注册/票据**（`Pek.IP::auth`）：配置 `PubKey` 时直接拒绝下载；`AutoEnroll`/`StateDir` 已进配置与文档，实现位置留在 `manager.ensureAll` 的验签分支。
- **在线 IP API**（`DH.NIP::OnlineIp` 的 ip-api/腾讯/高德/百度四格式）与 **DB-IP CSV→纯真转换**：解析与编码组件已就绪（`std.json` / `gb2312.Encoder`），CLI 子命令待加。
- **单请求超时**：std 0.17 `Client` 未暴露 per-request 超时；下载在后台线程，卡住不影响查询。收紧时在 `http.zig` 挂 `Io.Timeout`。
- **目录签名**（`catalog.json.sig`）：与 Ed25519 验签一起做。

### 验证（实测）

- 单测 **48/48** 通过（`zig build test`），含真实数据用例：
  - 真实 `ip2region_v4.xdb`：`114.114.114.114 → 中国|江苏省|南京市|0|CN`、`223.5.5.5 → 中国|浙江省|杭州市|阿里|CN`；
  - 真实 `dbip-country-lite-2026-10.mmdb`：`8.8.8.8 → US / 美国`；`dbip-asn-lite`：`8.8.8.8 → AS15169 Google LLC`；
  - 真实 `DH.NIP/ip.gz`：`114.114.114.114 → 中国–江苏–南京`、`8.8.8.8 → 美国–加利福尼亚州–圣克拉拉–山景城`；
  - 安装链路：`tests/data/ip2region-test.zip` 走完「哈希拒绝 → 安装 → 最新版本发现 → 打开 xdb → 查询 → 旧版本清理」。
- 一键回归 `tools/regression.ps1`：**失败 0、跳过 0**（48 用例基线 + 合成自检 3 项 + 真实数据自检 2 项 + 基准冒烟）。
- 性能（ReleaseFast，20 万次/项）：xdb 66 ns/op、MMDB 1547 ns/op、合并 1930 ns/op、保留地址 9.1 ns/op、4 线程并发 487 ns/op（聚合 2.05M QPS）。
