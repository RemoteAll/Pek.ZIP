# 用户档案（Pek.ZIP）

> 全项目通用偏好以用户级《跨项目接续协议》为准；此处只记与本项目相关的偏好与口径来源。

## 交流与推进

- 中文交流；偏好「直接推进 + 关键处确认」，不喜欢反复确认无关细节。
- **重大口径先确认再落文**：格式兼容、默认值、失败策略这类会影响其它系统的决定，先问一句再写死。
- 汇报只要「结论 + 证据」（`文件:行号` / 退出码 / 实测数字），不要复述工具已展示的内容。

## 技术口径（与本项目强相关）

- **Zig 实现必须考虑并发/异步**（2026-11-12 原话：「ziglang的实现都必须要考虑异步」）→ 本项目用「本地同步 + 后台线程 + 原子热替换」，并在 README 里写明为什么不是 await（Windows 上 std 0.17 socket 仍同步）。
- **验证一律走分档，不要动不动打包**：本项目的「验证」= `zig build test` + `zpk selfcheck` + `tools/regression.ps1`；发布打包另有其事。
- **实测优先、禁止猜测**：性能、容量、兼容性结论必须带命令与数字；写进 `README.md` 的性能表与 `docs/决策记录.md` 即为此用。
- **复用优先**：写码前先检索 `Pek.IP` / `DH.NIP` / 本仓库既有实现（本项目已把 `Blob`、`catalog`、`store` 的重复实现收口）。

## 安全与工程

- 密钥/凭据不明文落盘；不使用他人签名文件。
- 配了 `PubKey` 但验签未实现时**拒绝下载**（宁可不可用也不静默放行）。
- 中文 `.ps1` 一律 UTF-8 with BOM；PS 5.1 外部命令期间临时 `Continue` 并判 `$LASTEXITCODE`。
