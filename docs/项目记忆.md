### Zig 0.17 踩坑（本项目实际遇到）

- `std.Thread.Mutex` 已移除；用 `std.atomic.Mutex`（tryLock + spinLoopHint）或 `std.Io.Mutex`（需 io，返回 Cancelable）。
- 数组重复写法 `{0} ** n` 会报 "whitespace on one side"；改用 `@splat`。
- `std.mem.trimLeft`、`std.fmt.fmtSliceHexLower` 已移除；用 `std.mem.trim` / 手写 hex。
- `Dir.rename` 是方法：`old_dir.rename(old_sub, new_dir, new_sub, io)`（io 在最后）。
- `File` 无 `readToEndAlloc`；用 `file.reader(io, &buf)` + `reader.interface.allocRemaining(gpa, .limited(n))`。
- 结构体字段不能与同容器函数同名（`kind` 字段 + `kind()` 访问器 → 字段改 `db_kind`）；函数参数也不能同名（改 `wanted`）。
- `inline for` 里不能 `orelse continue`（comptime 控制流）；改普通 `for` 数组。
- 编译期表排序要 `@setEvalBranchQuota(200_000)`。
- mmap：`file.createMemoryMap(io, .{ .len, .protection = .{ .read = true } })`，`mm.memory` 是 `[]align(page) u8`，销毁要 `mm.destroy(io)`。
- gzip：`std.compress.flate.Decompress.init(&input, .gzip, &window)` → `decompress.reader.allocRemaining(...)`。
- zip：`std.zip.extract(dir, &file.reader(...), .{})`（已拒绝绝对路径与 `..`）。
- CA：`client.ca_bundle.rescan(gpa, io, std.Io.Clock.real.now(io))`。
- **别用 PowerShell 管道判断换行**：`git show HEAD:x.md | python ...` 会被 PS 转成 CRLF，误报「blob 里是 CRLF」；用 `cmd /c "git cat-file blob HEAD:x.md > out.bin"` 再看字节。（本仓库 `.gitattributes` 已是 `eol=lf`，blob 实测为 LF。）

### 2026-11-19 死循环事故（务必记住）

- **`Reader.takeDelimiterExclusive` 在真正 EOF 处反复返回 0 长度切片，不报 `error.EndOfStream`**；
  配 `line.len == 0 -> continue` 就是死循环（`zig build test` 表现为"卡死"，`test.exe` 单核 100% 但内存只 7 MB）。
  按行读必须用 `takeDelimiter`（返回 `?[]u8`，EOF 给 null）。
- **Windows 上对仍被 mmap 的文件再 `createFile`/`writeFile` → `USER_MAPPED_FILE → AccessDenied`**；
  测试里同一路径二次转换必须换独立输出文件（或先 `deinit()` 读取器）。
- 纯真数据区每条 = 4B `end_ip` + 区域串(GBK) + 0x00 + 地址串 + 0x00；累加 `data_offset` 必须含那 4 字节，
  否则第 2 条起索引偏移全部前移，读回的 end_ip 落在上一条串里 → 除首条外全查不到。
- 末条记录空地址段可能正好落在文件末尾（只剩 1 个 0x00）→ `readAddress` 不足 4 字节时按普通串读，不能判 `Corrupt`。
- 远端：`origin https://github.com/RemoteAll/Pek.ZIP.git`，分支 `main`。

### 2026-11-19（八）省流量 + 自动升级（常驻进程）

- **省流量四条**（都有实测）：目录 TTL（CatalogMaxAge）、本地齐全不联网（`ensureAll` 早退）、
  只在远端版本更高时下包（`compareVersions`）、同机 `.sync.lock` 只下一次。
- **新补：常驻进程自动更新** —— `Config.AutoUpdateMinutes` / `StartOptions.auto_update_minutes`（默认 0 关闭）：
  worker 首轮后循环「`Io.Condition.waitTimeout` 等待 → `syncPass(true)`」；**无新版本不重建定位器**；
  `destroy()` 置 stop + signal → 立即退出不等满间隔。
- **`waitIdle()` 语义已改**：等「首轮完成」(finished + ready_cond)，**不再 join**（否则开定时更新会永久阻塞）；
  线程回收在 `destroy()` 的 `joinWorker()`。
- 带宽账：每轮 1 次 catalog.json（≈85 KB，TTL 内走缓存=0），每天最多约 340 KB。
- 坑：配置 `StoreUrl = ""` **不会置空**（applyToml 空值保持默认 → 回落到 p.sc8.fun）；测试要用 127.0.0.1:1。

### 2026-11-19（四/五）请求超时：源码核对 → 最终用原生取消（复用 zzig）

- **Zig 0.17.1 底层有超时、`std.http.Client` 没接**：
  `Io.net.ConnectOptions.timeout` 生效（`io.vtable.netConnectIp`）、`Socket.sendTimeout/receiveTimeout` 生效（`operateTimeout`）；
  但 `Client.ConnectTcpOptions.timeout` 是**死字段**（`connectTcpOptions` 从不读取，内部 `host.connect(io,port,.{.mode=.stream})` 丢掉了），
  `Client.zig` 全文仅此一处 timeout，`RequestOptions` 无；`Io.Operation` 没有 `net_connect`。
- **最终实现（复用生态，不要自造）**：`G:\Code\Zig\zzig\src\http\http.zig::fetchBytesWithTimeout`
  （zzig `minimum_zig_version = "0.17.1"`）就是原生做法：`io.concurrent(fn,args)` → 超时 `future.cancel(io)`
  （**cancel 会请求取消并等任务结束 = join**）。本项目 `src/http.zig::runWithTimeout` 照此实现，
  等待改用 `Io.Condition.waitTimeout`（比 zzig 的轮询+sleep 更省）。
  **别再自造 detached 线程看门狗**（真卡死会漏线程）。`WuKong-Lite` 是 Python 工程，经验不能直接搬。
- 配置 `HttpTimeoutMs`（默认 120000，0=不限）。
- **0.17 API 坑**：`std.Thread.Mutex/Condition` 已移除 → 用 `std.Io.Mutex/Condition`（`.init`，`lock(io)`、`waitTimeout(io,&m,timeout)`）；
  `std.time.nanoTimestamp` 已移除 → `Io.Clock.real.now(io).nanoseconds`；
  `Io.Timeout.duration` 要 `Clock.Duration{ raw: Io.Duration, clock = .real }`（不是 `Io.Duration`）。
- 坑：`Set-Content -Encoding utf8` 写配置带 **BOM** → 首行 `StoreUrl` 解析失败回落默认平台；造配置一律写无 BOM UTF-8。
- 实测：本地「只 accept 不回包」监听 + `HttpTimeoutMs=1200` → `zpk sync` **1.25s** 返回 Timeout。

### 2026-11-19（十一）本机镜像 MirrorUrl（跨库打通 Pek.RAgent）

### 2026-11-19（十五）镜像签名三件套（必记）

- **镜像必须转发 `.sig`**：客户端用自己 TOFU 的平台公钥校目录签名；镜像不存 `.sig` 就等于「目录不可验证」。
  RAgent 侧改为「平台给什么签名就存什么」，`IpdbPubKey` 只决定镜像侧要不要验。
- **坑：`dhrust::net::static_files` 只下发 MIME 表已知扩展**，`.sig` 不在表里 → 文件在盘上但
  `/ipdb/catalog.json.sig` 返回 404。改为手工 `fs::read` + `HttpResponse::bytes`；组件包仍走 StaticFiles（`.zip` 有 MIME）。
  以后加非常规扩展名的静态文件（`.sig/.bin/自定义`）先想这条。
- **客户端兜底**：`Manager.verifyCatalogSig()` 失败且当前用的是镜像 → 整段回退平台重取并重新验签；
  用平台则硬失败。实测两种态：删 `.sig` → 回退日志 + exit 0；恢复后 → 直接用镜像、无 404。

### 2026-11-19（十六）镜像缓存自动回收

- **问题**：镜像按「文件名含版本」保存，从不清理 → 每月发版多 ~13 MB（开 v6 再加 37 MB），长期跑会把盘吃满。
- **做法**：每轮刷新收集「当前目录引用的文件名」，末尾删除不在集合内的文件；**`keep` 为空时绝不清理**（安全阀）。
  语义以「当前目录 + 当前配置」为准：关掉 `IpdbIncludeV6` 后 v6 会被清掉，需要时再开重下。
- **可观测**：日志「刷新完成…清理 N…」+ 每条「清理旧组件 xxx」；`/star/ipdbStatus` 的 `lastPruned`；面板缓存卡显示四项计数。
- 实测：预置 `ip2region-v4-2020.01-any.zip` → 刷新后日志「清理旧组件 …（不再被当前目录引用）」，目录只剩当前 3 包。

### 2026-11-19（十七）平台每日配额 20 次 + 快照落盘（重要运维事实）

- **平台对每个下载身份限「20 次/天」包下载配额**（今天反复联调耗尽了，报 `今日下载配额已用完（20 次/天）`）。
  正常月更（4 个数据集）远够用；反复手动刷新、多台机器共用一个身份会撞上限。
- 由此补了清理的**第二道安全阀**：本轮若有引用的包未就位（下载失败/配额），**跳过旧版本清理**并告警，
  避免把旧包删掉、镜像连该数据集一起丢。
- **刷新快照落盘** `Ipdb/last-refresh.json`（原子写）：服务重启后面板仍显示上次刷新时间/新下载/复用/清理/告警
  （原先只存内存，重启后全是 0，看起来像"刚刷过且一切正常"）。
- Pek.ZIP 侧：`error.Denied` 提示改为「看『平台返回错误』的 message：未批准 / 配额用尽 / 身份不匹配」，
  不再一律指成「installId/公钥问题」。
